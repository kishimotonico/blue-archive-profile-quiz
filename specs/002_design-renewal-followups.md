# デザイン刷新後の残課題

デザイン刷新のレビュー（Fable と Astra）で挙がった設計改善案のうち、まだ対応していないものをここにまとめます。プレイ状態の controller 化、Provider の一本化、モバイル/デスクトップのレイアウト分離、`Modal` の `<dialog>` 化、開示段階の純粋関数化は対応済みです。

## 方針

このリファクタは保守的に進めない。既存構造を壊してでも、いちばん素直な設計にする。

- 互換性を守るのは、過去の `QuizKey` からの問題再現（`QuizKey.version` で世代管理している出題関数を凍結する）と、日替わりの回答履歴
- レアケースへの処理、過度なフォールバック、回復策は入れない。「こうなると危ないから」を理由にした判断もしない
- 「今の実装がこうだから」を理由に残す構造はない。既存の props・型・ファイル配置を維持する必要はない

## 進め方

依存関係のあるものだけをまとめて、別々の PR に分けます。

1. 演出の実行条件を決めてから、ヒント開示のアニメーションを作る（下の「演出」）
2. 立ち絵の描画を共通化する（下の「立ち絵の描画」）
3. ヘッダーのドロワーの Escape 処理を整理する（下の「ドロワー」）
4. 部品を増やすタイミングで、色と部品の使い方を決める（下の「色と部品」）

## 演出

今は動きの実装が3種類あります。CSS の keyframes（開示時のきらめき `ba-shine`、立ち絵の展開 `ba-portrait-grow`、シルエットのフェードイン、リング）、motion ライブラリ（`AnswerInput` の入力欄のシェイク）、レイアウト側の `scrollIntoView` です。

- 技術を1種類に揃えることより、実行条件を先に決める。新しく開示したときだけ再生する。保存からの復元では再生しない。次の問題に進んだら中断する。動きを減らす設定のときは、すぐ最後の状態を出す
- 今は `HintList` の `animateReveal` を `round.status === "playing"` から渡しているだけで、再開した直後の途中状態でも再生される。「いま開示した」ことを表す条件を決める
- 回答確定でヒントや立ち絵が一括で開くときの演出を決める。今はヒントのきらめきを出さない
- 1回の開示の流れ（カードが開く、立ち絵が出る、スクロールする）は、担当する hook かコンポーネントを1つにする。必要なら motion に寄せる。ボタンのホバーやリングの単純な遷移は CSS のままでよい
- ゲームとしての開示状態はすぐに確定させる。演出が終わるのを、保存や回答の前提にしない
- 動きを減らす設定への対応は、CSS の演出と、モバイルのなめらかなスクロール（`MobileQuizLayout`）に入っている。motion のシェイクにはまだ入っていない
- 演出の長さは CSS（`index.css`）の秒数と、それに合わせる処理で二重に持たない

## 立ち絵の描画

- 立ち絵の画像とシルエットの処理が、`MobilePortraitCard`、`StudentPortrait` のデスクトップ用パネルと全身モーダルの3か所にある。シルエットの作り方も場所によって違う。URL・読み込み失敗時の画像・シルエットの表現だけを `PortraitImage` にまとめ、切り抜きやサイズは呼び出し側に残す
- `useDailyQuiz` / `useRegularQuiz` が `components/quiz/portraitImageUrl` を import している。hook と component の両方から使うものは、別の場所に置く

## ドロワー

ヘッダーのドロワー（`Header.tsx`）は、`Modal` とは別に `document` の keydown で Escape を処理している。ドロワーは全面オーバーレイで背後を塞ぐので、`Modal` とは同時に開かず今は競合しない。`<dialog>` に乗せられるか検討し、乗せないなら別の Escape listener を残す理由をコメントに書く。

## 色と部品

- 青は装飾・文字色・白文字を載せる面・フォーカスのリングと、用途が広い。用途がぶつかる色にだけ、意味のある別名を足す。トークンをすべて作り直す必要はない
- ボタンの見た目の状態は `Button` の中にまとめ、呼び出し側の `className` は幅・配置・余白だけにする。今は `AnswerInput` が「回答する」の disabled の透明度を `disabled:opacity-80!` で上書きしている
- `rounded-2xl border border-ba-border bg-white` の直書きが `Result`・`QuizPlayArea`・`StudentPortrait`・`DesktopQuizLayout` に6か所ある。`.ba-card`（白い面）と `.ba-card-muted`（淡い面）程度のクラスにまとめる。背景・枠線・角丸だけにして、余白や高さまでは共通にしない

## 見送ったもの

- 開示ボタンに「（残り6）」のような残り数を添える。ボタンはシンプルに保ち、残り数はリングで示す
- アプリ内の動きをすべて1種類の技術で書く（Fable の提案）。上の「演出」のとおり、実行条件と開示の流れの担当を揃えることを優先する

## 今の方針のまま、将来見直す余地があるもの

- デスクトップの立ち絵は、絵の上端に合わせてバストアップに切り抜いている（`StudentPortrait` の `object-cover object-top`）。切れ方は絵によって違い、生徒によっては顔が枠の上端に寄る可能性がある。崩れる生徒が見つかったら、全身を収める（`object-contain`）か、生徒ごとに切り抜く位置をデータで持つかを検討する
- 回答前のデスクトップでは、右カラムのいちばん大きな面が「?」だけになっている。リングの数字には単位がない。いま正解すると何点かを示すなど、この面の使い方は検討の余地がある
- タブレット幅（768〜1023px）はモバイル型のクイズ画面になり、ヒント一覧の下に大きな空白ができる
